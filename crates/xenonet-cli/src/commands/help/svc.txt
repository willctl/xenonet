A local HTTP service this machine publishes to its XenoNet network. A
program on another machine in the network reaches it through that
machine's own XenoNet, as if it ran there:

  http://127.0.0.1:<its XenoNet's port>/api/svc/<this host>/<name>/<path>

The request crosses sealed, like everything between machines, and the
gateway can't read it. XenoNet knows nothing of what the service is.

  xenonet svc list [--json]        what this machine publishes
  xenonet svc unpublish <name>     takes a service off the network

Publishing widens what the network can reach, so it asks you (Touch ID
on a Mac) and is done in XenoNet's window: Network settings › Publish a
service. A service listens on this machine's loopback address (127.0.0.1
or [::1], by IP, plain http), and only the paths you list under it are
reachable. Every host in the network may call it, or only the hosts you
name. Publishing a name again replaces it. xenonet svc publish says so
and does nothing.

This machine's XenoNet sends the service each request with a Forwarded
header naming the calling host (Forwarded: by=xenonet;for=laptop). Only
the caller's Authorization, Content-Type, Accept and User-Agent headers
cross, and the answer comes back without Set-Cookie. A request's body is
at most 1 MiB, an answer's 4 MiB, and each host may call each service
300 times a minute. A caller waits 90 s at most, and gets 503 when the
host is offline.

A service with no sign-in of its own is open to every program on every
host allowed to call it: give it its own tokens, or name the hosts that
may call. Taking a service off is yours to do, from the window or your
own terminal: XenoNet refuses it from under an agent.
