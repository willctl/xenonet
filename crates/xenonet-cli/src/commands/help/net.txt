XenoNet networks across your machines. A machine can be in several, with
a host id of its own in each. The machines reach each other straight, over
QUIC: on your LAN, by direct paths, or through a relay when the network
names one, so no machine opens a port and nothing needs SSH keys. What
one machine sends another is signed by it and sealed for the one it's
for: a relay or a mailbox passes it on and can't read it.

What acts on one network takes --network <id|name>. A machine in one
network needs no --network; one in several is asked which.

  xenonet net create --name <name> --host <id> [--relay <url|n0>]
                                   makes a network, beside any this machine
                                   is in, with this machine as its founder.
                                   --relay names the network's relay: your own
                                   iroh-relay's URL, or n0 for n0's public
                                   relays (rate-limited, run by n0). With
                                   none, machines reach each other on the
                                   LAN and by direct paths only
  xenonet net invite <id> [--window] [--mdns]
                                   an invite for a new machine, and its code
                                   apart: give it the invite, and tell it the
                                   code some other way. It works once, for
                                   ten minutes, and five wrong codes retire
                                   it. --mdns lets the new machine find this
                                   one on your LAN. It's XenoNet's window's,
                                   since signing the machine in asks you
  xenonet net join <invite> <code> [--at <ip:port>] [--mdns]
                                   joins the network straight from the
                                   machine that made the invite: at its
                                   address (--at, such as its tailnet or LAN
                                   address), on your LAN (--mdns), or through
                                   the network's relay when it has one
  xenonet net status [--json]      each network, this machine in it, and
                                   what's held for a machine that's away
  xenonet net hosts [--json]       the machines in each network
  xenonet net remove <id>          takes a machine out of the network
  xenonet net revoke-device        revoking a lost machine's device is
                                   XenoNet's window's (Network settings ›
                                   Your devices), since it asks you
  xenonet net replace <id>         takes a reinstalled machine's old keys out,
                                   and makes an invite for it to join again
  xenonet net leave [--force]      asks to be taken out, then forgets the
                                   network here; the others this machine is
                                   in carry on as they were
  xenonet net share all|none|<prj_…,…>
                                   which projects' sessions the network sees
                                   of this machine. The first network sees
                                   all; one after it starts with none.
                                   Sharing more is XenoNet's window's, since
                                   another network's members then see it
  xenonet net relay [add|remove] <url|n0> [--mine]
                                   the network's relays: your own
                                   iroh-relay's URL, or n0 for n0's public
                                   relays. Adding one widens the network, so
                                   it's done from XenoNet's window and takes
                                   the founder or a second window host;
                                   taking one out is done at once. With
                                   --mine, a relay of this machine's own, in
                                   no network's chain, for its own dials.
                                   This machine's home relay is one every
                                   network it's in lists; with none such,
                                   one of its own. With no word, the
                                   relays as they stand
  xenonet net set [--titles-only | --no-titles-only]
                  [--share-load | --no-share-load]
                  [--start off|you|network|delegate] [--wake consent|network]
                                   what this machine shares with the network
                                   (its load: CPU, GPU, memory and the parts,
                                   on by default), who may start sessions here (you,
                                   by default; network adds the network's
                                   sessions and actors; delegate is the
                                   network, with what they start running
                                   under your delegation) and who may wake
                                   them for a message (your consent per
                                   session, by default, or the network).
                                   Start and wake are entries in the
                                   network's chain: narrowing is done at
                                   once, and widening asks you, so it's done
                                   from XenoNet's window. Your delegation is
                                   an entry in your own chain, signed by
                                   your device: it names your devices (all
                                   of them, unless you narrow it), lets
                                   them start sessions and allow routine
                                   prompts inside the session's folder for
                                   work you started on any of them, and
                                   lasts a year. Setting delegate makes it
                                   when none names the machine's device,
                                   which asks you once more
  xenonet net set --on <id> [--start …] [--wake …] [--approve <id>]
                                   another machine's start and wake, from a
                                   window host. Narrowing is done at once;
                                   network and delegate ask you, so they're
                                   set from XenoNet's window, and take the
                                   founder, or wait for another window host
                                   to --approve it there. Delegate needs the
                                   machine to have a device of yours, which
                                   your delegation names
  xenonet net approve <id> [--op <op>]
                                   approves what waits for approval about a
                                   machine, such as its add as a window
                                   host, and shows what it approves. Several
                                   waiting: name one by the entry id the
                                   answer lists

Creating, joining and leaving are yours to do: XenoNet refuses them from
under an agent. The founder's key is the network's root: a network whose
founder is lost is made again.
