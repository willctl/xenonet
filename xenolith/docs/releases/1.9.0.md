# Xenolith 1.9.0

Xenolith now installs from one download. Each release has an archive for macOS (Apple silicon and Intel), Linux x64 and Windows x64 holding both programs and the window's files, so a machine needs no Rust, Node or checkout to install it.

This release also changes who may do what. Only direct requests on this machine count as local, decisions need the owner key, and every note records who sent it. Sync between machines keeps going through ordinary failures, and the shared context folder's format has a written spec.

## Install

Download the archive for your machine and `SHA256SUMS` from this release. Unpack the archive anywhere and run `xenolith install` in the unpacked folder. The installer copies the programs into Xenolith's own folders, so you can delete the download afterwards. A later release's `xenolith install` upgrades in place and leaves what the shared context holds alone.

| Machine | Archive |
| --- | --- |
| Mac with Apple silicon | `xenolith-1.9.0-darwin-arm64.tar.gz` |
| Mac with an Intel processor | `xenolith-1.9.0-darwin-x64.tar.gz` |
| Linux x64 | `xenolith-1.9.0-linux-x64.tar.gz` |
| Windows x64 | `xenolith-1.9.0-win32-x64.zip` |

### macOS

```bash
cd ~/Downloads
curl -LO https://github.com/willctl/xenonet/releases/download/xenolith-v1.9.0/xenolith-1.9.0-darwin-arm64.tar.gz
curl -LO https://github.com/willctl/xenonet/releases/download/xenolith-v1.9.0/SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf xenolith-1.9.0-darwin-arm64.tar.gz
cd xenolith-1.9.0-darwin-arm64
./xenolith install
```

On an Intel Mac, use `darwin-x64` in the names. The programs are signed ad hoc and not notarized, so macOS refuses to run them when a browser downloaded the archive. Download with `curl` as above, or run `xattr -dr com.apple.quarantine xenolith-1.9.0-darwin-arm64` on the unpacked folder before installing. The programs go to `~/Library/Application Support/Xenolith`.

### Linux

```bash
curl -LO https://github.com/willctl/xenonet/releases/download/xenolith-v1.9.0/xenolith-1.9.0-linux-x64.tar.gz
curl -LO https://github.com/willctl/xenonet/releases/download/xenolith-v1.9.0/SHA256SUMS
sha256sum -c SHA256SUMS --ignore-missing
tar -xzf xenolith-1.9.0-linux-x64.tar.gz
cd xenolith-1.9.0-linux-x64
./xenolith install
```

It runs on glibc 2.39 or later, such as Ubuntu 24.04 or Debian 13. The tray needs GTK 3, WebKitGTK 4.1 and the Ayatana app indicator. On Debian or Ubuntu: `sudo apt install libgtk-3-0 libwebkit2gtk-4.1-0 libayatana-appindicator3-1`. The programs go to `~/.local/share/xenolith`.

### Windows

Open a normal terminal (Win+R, `cmd`, Enter), not the terminal inside the Claude or ChatGPT desktop app. Then:

```bat
cd %USERPROFILE%\Downloads
certutil -hashfile xenolith-1.9.0-win32-x64.zip SHA256
tar -xf xenolith-1.9.0-win32-x64.zip
cd xenolith-1.9.0-win32-x64
xenolith.exe install
```

Compare the hash `certutil` prints with the zip's line in `SHA256SUMS`. Approve the administrator prompt: it registers the Xenolith service. The programs aren't signed, so Windows may say the publisher is unknown. They go to `%LOCALAPPDATA%\Xenolith`.

### After installing

Restart the Claude and ChatGPT desktop apps so they load the plugin and the server. Then sign the curator in once: tray icon > **Curator** > **Sign in to ChatGPT for the curator...**. Until then, notes wait in the inbox. `xenolith uninstall` takes Xenolith out of the apps again, and the [README](https://github.com/willctl/xenonet/blob/main/xenolith/README.md) says what it leaves in place.

## Moving from agent-wiki

Install Xenolith first, then run `xenolith migrate agent-wiki` to move an agent-wiki install over. The [README](https://github.com/willctl/xenonet/blob/main/xenolith/README.md)'s section on moving from agent-wiki says what it moves and lists its options.

The tools are now `context_start`, `context_search`, `context_read`, `context_log` and `context_upsert_page`. Sessions that still call the agent-wiki names (`wiki_start` and the rest) keep working in this release.

## Who is local

A request is local only when it reaches the service's loopback port directly and carries no `Forwarded`, `X-Forwarded-*` or `Via` header. Before, a request counted as local whenever its Host named loopback, so a forwarder that rewrote Host got full access.

- Sync always needs a token, even from this machine.
- `/status`, the window and its API refuse forwarded requests. `/health` no longer names the folder.
- A plain tunnel such as `ssh -L` still looks local. If anything reaches the port that way, `xenolith access local none` takes local access away, and each client then needs its own token.
- After 20 bad tokens in a minute from one source, requests with a token from it get 429 for a minute.

## The owner key and approvals

Approving or denying held changes and proposals, Undo, Revert, the Approvals setting and Forget now need the owner key. The service writes a new key at each start to a file only you can read. The tray passes it to the window, and `xenolith held approve|deny|refile` reads it and asks the service.

Any other local process can read the window's API but can't decide anything, so an agent can't approve its own change, and whoever sent a note behind a change can't approve that change. Each decision and each refused attempt goes in the audit chain with who made it. An agent running unsandboxed as you can still read the key file, as it can read any of your files.

## Notes say who sent them

The server stamps each note with its sender: the app for a process on this machine, the token's subject over HTTP or sync, or the owner for notes made in the window or with the new `xenolith note` command. Only the owner's notes may have the source `user`. From anyone else it is recorded as `agent`, so passing `user` no longer makes a preference stick or gets a note past the holds.

Reads return content only. `context_read` reaches `pages/`, `log/`, `inbox/` and the top-level `index.md`, `PROTOCOL.md` and `README.md`, never the curator's held changes, journals, audit records or `.history/`. A token reaches this machine's own space, `machine:local`, only when its grant and its scopes name it exactly.

## Sync between machines

- Entries the curator refuses for good (403 or 400) move to `.curator/sync/dead/` with the reason and aren't sent again. `xenolith sync status` counts them.
- A failed push no longer skips the pull, and a page gone from the curator no longer stops one.
- A follower pins the curator it first pulled from, and refuses to sync with another curator of the same space until you follow the space again.
- Removals travel. The curator lists pages removed in the last 30 days, and followers move their copy to `.history/`. A page removed in a copy is sent as a removal.
- A page changed in a copy since the last pull is sent against the version last pulled. If the curator's page moved on, it becomes a proposal for you to decide. A change still waiting to be sent is never overwritten.
- Followers pull the curator's last 7 days of log, so `context_start` on a copy shows recent activity.
- One request may take 90 seconds by default; `xenolith sync timeout` changes it.
- A note that sync sent or refused still opens as `note:<id>`.

## The folder's format

[FORMAT.md](https://github.com/willctl/xenonet/blob/main/xenolith/FORMAT.md) describes format 1 of the shared context folder: how to find it, the layout and spaces, page frontmatter, links, the log's grammar, note ids and inbox notes. At each start the server writes `xenolith.json` at the folder's root, `{"format": 1, "server": "xenolith"}`, so another program can tell what wrote the folder and which format it is in.

## "Shared context"

What agents and people read now says "shared context" or "page" instead of "the wiki": the tool descriptions, `PROTOCOL.md`, the instruction block, the hook's messages, the tray and the window. The tray's "Open wiki folder" is "Open folder". An install replaces `PROTOCOL.md` with this release's when you haven't edited it. Settings and options keep their names, such as `wikiDir` and `--wiki-dir`.

## New LaunchAgent labels on macOS

The server, the curator and the tray's login item are now `dev.xenolith.server`, `dev.xenolith.curator` and `dev.xenolith.tray`. The installer stops and removes the old `dev.xenonet.xenolith.*` jobs first, the tray's first, so two trays or two servers never run at once. Uninstall removes both sets. There is nothing for you to do.

## Also new since agent-wiki 1.8.0

- Spaces, with read, append, write and admin access kept in `access.json` in the config folder.
- Bearer tokens with `ctx:*` scopes for other apps and machines.
- An audit chain of grants, tokens, refusals and writes, with hashes instead of text. `xenolith status` reports the service and the chain.
- Pages as MCP resources with update notifications, and the start rules as an MCP prompt.
