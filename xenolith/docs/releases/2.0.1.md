# Xenolith 2.0.1

On macOS, the 2.0.0 service stopped answering after a while: it kept a file open for every file in a space folder and one more each time a page was written. Once it reached the system's limit of 256 open files, apps lost their connection to it. 2.0.1 fixes that.

## Changes

- **The service keeps few files open on macOS.** It watches the shared context folder with FSEvents, which holds no file per page. It still follows the pages and folders it syncs on their own, so changes reach other machines within a second or two, but it closes each one when the file is replaced, and it never follows more than its share of the open-file limit.
- **Sync catches up on its own.** If no change is heard, the service checks the folders it syncs every five seconds, so a change can't wait on a late file event.

## Upgrading from 2.0.0

Run `xenolith install` from the unpacked 2.0.1 archive. It upgrades in place and restarts the service. Nothing in the shared context changes.

To upgrade from 1.x, follow the steps in the [2.0.0 notes](2.0.0.md#upgrading-from-1x), with the 2.0.1 archive.

## Install

Download the archive for your machine and `SHA256SUMS` from this release. Unpack it anywhere and run `xenolith install` in the unpacked folder. The [2.0.0 notes](2.0.0.md#install) have the steps for each system; use `2.0.1` in the names.

| Machine | Archive |
| --- | --- |
| Mac with Apple silicon | `xenolith-2.0.1-darwin-arm64.tar.gz` |
| Mac with an Intel processor | `xenolith-2.0.1-darwin-x64.tar.gz` |
| Linux x64 | `xenolith-2.0.1-linux-x64.tar.gz` |
| Windows x64 | `xenolith-2.0.1-win32-x64.zip` |

```bash
cd ~/Downloads
curl -LO https://github.com/willctl/xenonet/releases/download/xenolith-v2.0.1/xenolith-2.0.1-darwin-arm64.tar.gz
curl -LO https://github.com/willctl/xenonet/releases/download/xenolith-v2.0.1/SHA256SUMS
shasum -a 256 -c SHA256SUMS --ignore-missing
tar -xzf xenolith-2.0.1-darwin-arm64.tar.gz
cd xenolith-2.0.1-darwin-arm64
./xenolith install
```
