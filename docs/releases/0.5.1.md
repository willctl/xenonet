# XenoNet 0.5.1

On Windows, XenoNet's service opened and closed a console window every time it ran git or another program in the background, several times a second when you have a few repos. This release keeps those windows hidden. Desktop and Tools are 0.5.1, the Service is 0.5.2 and the Mac tray is 0.4.1.

## Fixes

- **Windows: no more flashing windows.** Every program the service, the hooks and the `xenonet` command start in the background (git, PowerShell, the apps' own commands) now starts with no window of its own. A test checks that each one does, so a new one can't bring the windows back.
- **Grok Build's messages at session close.** Grok fires one more Stop as its session closes and reads no answer to it. XenoNet took the session's messages then, so they were marked read and lost. They now wait for the session's next turn.
- **Grok Build's edits.** Grok's own edit tools (`search_replace`, `write` and the rest) count as edits, so the map draws collisions with them and other sessions are warned about the files.
- **Other apps on Claude Code's hooks.** Cursor and Grok Build run Claude Code's hooks too, with their own input. XenoNet passes over those events, so a Cursor session can't show as a Claude Code one on Linux or Windows, and on a Mac they no longer fill the refusals log.

## Updating

1. Update Desktop. On Windows, open **Updates** and choose **Restart and update**. On a Mac, replace XenoNet in Applications with the copy from the new disk image, and open it.
2. Update the Tools, then the Service: in **Updates**, or with `xenonet update tools` and then `xenonet update service`. On Windows the Service update is the one that stops the windows. If terminals are open in XenoNet, the Service update waits until you close them and choose Update again.

Without Desktop, download the Service and Tools archives and run `./bin/xenonet setup` from the Tools folder, then from the Service folder.

`SHA256SUMS.txt` lists checksums for the downloads.
