# XenoNet 0.3.0

A message to another session can now reach it while it's idle, instead of waiting for its next turn. This release also adds a Needs you panel, spend by actor, posters and films that are redacted by default, and experimental readers for more harnesses. Service and Tools are both 0.3.0.

0.2.0 wasn't released on its own. Its changes come with this release: provider refusals, agent workflows, fewer false stall warnings and gateway tokens a session can ask for. Its [notes](https://github.com/willctl/xenonet/blob/main/docs/releases/0.2.0.md) describe them.

## Messages that wake a session

XenoNet puts a message into the session it's for the first way that works, and otherwise the session's hooks hand it over on its next turn, as before. Run `xenonet doctor --live` to see what each way needs here and the commands to start sessions with them. The [live delivery guide](https://github.com/willctl/xenonet/blob/main/docs/guide/live-delivery.md) has the details.

- **Claude Code, idle.** Start Claude Code 2.1.80 or later with `claude --dangerously-load-development-channels server:xenonet`. The message arrives in the session and it answers. Channels are a Claude Code research preview, so Claude Code asks you to confirm at each start.
- **Claude Code after a turn, headless runs too.** Start a session with XenoNet's listen settings (`claude --settings …`, printed by the doctor). For five minutes after each turn, a message that comes keeps it going. This works in `claude -p` runs, which channels don't reach.
- **A Claude Code or Codex session that has ended.** If you allow it with `xenonet live allow <session>`, XenoNet resumes it for one turn with the message (`claude -p --resume` or `codex exec resume`), in its own folder, and never while it still runs.
- **OpenCode.** Start OpenCode with `--hostname 127.0.0.1` and allow the session. XenoNet posts to the server of the OpenCode that has it open. OpenCode sessions can message each other by name. `scripts/demo/opencode-named.mjs` runs two or three of them doing so, and prints how long each step took.
- **tmux.** For a session you allowed, XenoNet types the message into its pane as one line, only when you or an actor with a token sent it.

The sender's answer says which way each message is going. If nothing picks a message up within a minute, XenoNet tells you, and the session still gets it on its next turn.

## Scopes and guards

- `send` and `peers` take selectors such as `project:atlas app:opencode status:idle`.
- An actor sees and reaches no session until you grant its token a scope: `xenonet live grant <actor> <scope>`. Grants expire, `xenonet live revoke` takes one away at once, and one identity's sessions stay apart from another's.
- Each wake starts a turn on someone's plan. Wakes are limited per sender and per session, and a provider at 90% of its plan takes none. `xenonet live` shows the plans as XenoNet reads them.
- Rate and fan-out limits stop floods and loops between agents. Keys and tokens are redacted when a message crosses identities or involves an actor.
- `xenonet live pause` stops every message and wake at once. The command palette has the same switch. An append-only audit log keeps a hash of each message, never its text.

## Needs you

Press `N`, or choose Needs you in the command palette. One list has everything waiting on you, the longest wait first: sessions with a question or a permission prompt, actors waiting on you, programs asking to join and gateway token asks. Allow and Deny there are yours alone. The tray menu, the window title and `xenonet status` show the same list.

## Spend by actor

Token use shows what each actor's work cost today, at API prices, and so does `xenonet spend`. A session counts for the actor whose run it is, the actor that started it, or its parent's actor, and anything else is unattributed.

## Posters and films

Posters and films of your day are redacted by default. Star names stand in for project names, and no clock is shown. A poster comes in four sizes, with a preview, and you choose what to reveal. A film runs 15 to 30 seconds. Both stay on this computer.

## Experimental

- **More harnesses on the map.** XenoNet can read OpenCode, Gemini CLI and Copilot CLI sessions from their own records, and Cursor's through a hook. Each is off unless `XENONET_READERS` names it. They count in edit warnings and can't be messaged yet. The [related work guide](https://github.com/willctl/xenonet/blob/main/docs/guide/related-work.md) says what each reads and never reads.
- **Runs from elsewhere.** numbat's sessions, and runs an actor reports through the gateway's `report_run`, appear as sessions marked observed.
- **Sandbox results.** Review sandbox changes in the command palette brings a sandbox's text changes back as a diff. It exports only the patch you reviewed, and never changes your checkout.
- **Shared context.** Xenolith, which came from Agent Wiki, is now in this repository. When Xenolith is on this computer, the map shows its pages as a constellation of their own. It isn't in the installers yet. See the [shared context guide](https://github.com/willctl/xenonet/blob/main/docs/guide/shared-context.md).

## Fixes

- New transcripts are no longer missed on Linux. A folder that changed within the same tick of the filesystem's clock was skipped there.
- After a restart, lines written to a known transcript while XenoNet was stopped show as live, not as history.
- A reply to your own message goes to the same audience as the message, not back to you.
- An actor's `whoami`, `who_has` and claims stay inside its scope.
- The map keeps to a frame budget and draws nothing while the window is hidden, covered or locked.
- A Claude Code channel now registers. XenoNet's server answers it on MCP's 2025 handshake, the only one Claude Code accepts channels on.
- XenoNet now checks requests made in an OpenCode session's name against OpenCode's own processes.

## Updating

On Windows, open **Updates** and choose **Restart and update** for Desktop. Then install the Service and Tools updates there, or run `xenonet update all`.

On a Mac, replace XenoNet in Applications with the copy from the new disk image, and run `xenonet update all`. Your settings stay in place.

Without Desktop, `xenonet update all` is the whole update. The service update waits while XenoNet's terminals run, so close them first.

`SHA256SUMS.txt` lists checksums for the downloads.
