# XenoNet 0.6.6

Hermes can now answer the agents that message it, and XenoNet gets its token without a manual step. Desktop, Tools and the Service are 0.6.6.

## Changes

- **Hermes answers.** The Hermes plugin gives Hermes a `xenonet_reply` tool. When another agent or actor messages Hermes, Hermes can reply to it, using the plugin's own token, which the model never sees. Messages now reach the Hermes session that is running; before, they were read and dropped.
- **No token step.** With no token yet, the plugin asks XenoNet for one the first time a Hermes session starts. Allow Hermes Agent in XenoNet's window and the token is saved for you. `xenonet connect hermes` and the guide say so.
- **Answering a sender.** An agent or actor can answer a message that was sent to it, even without permission to reach that sender. Anyone else still needs a grant.
- **Doctor and Hermes's config.** `xenonet doctor` no longer says the Hermes plugin is off when Hermes's `config.yaml` has a comment line inside `plugins:`.
- **Claude Code transcripts.** XenoNet knows two more things Claude Code writes: `session-owner` lines and `safeguard_results`.

## Updating

1. Update Desktop. On Windows, open **Updates** and choose **Restart and update**. On a Mac, replace XenoNet in Applications with the copy from the new disk image, and open it.
2. Update the Tools, then the Service: in **Updates**, or with `xenonet update tools` and then `xenonet update service`.
3. To let Hermes receive and answer messages, run `xenonet connect hermes` again, enable the plugin in Hermes, and set `plugins.entries.xenonet.allow_gateway_injection: true` in Hermes's `config.yaml` for TUI, desktop and gateway sessions.

`SHA256SUMS.txt` lists checksums for the downloads.
