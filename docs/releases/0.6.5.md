# XenoNet 0.6.5

XenoNet now shows what Hermes and OpenCode say their sessions used and cost, and can follow both live. It also recovers better from restarts and crashes, and says what to do when it isn't running. Desktop, Tools and the Service are 0.6.5.

## Changes

- **Hermes and OpenCode usage.** A Hermes actor shows the tokens, the cost Hermes totalled and the models and providers that used the most. An OpenCode session shows its cost, tokens and model. A subscription or unknown price counts as unpriced, never as free. Spend by actor lists this as "reported" beside XenoNet's own estimate at API prices and never adds the two.
- **OpenCode live.** OpenCode's XenoNet plugin now tells XenoNet when a session is working, idle or waiting for you, which files it edits and what a reply cost. A waiting OpenCode shows in Needs you. Without the plugin, XenoNet reads OpenCode's database as before. It also reads OpenCode 2's new session tables.
- **Hermes plugin.** `xenonet connect hermes` installs a small plugin that reports a Hermes session's start, end, tools used and subagents, and lets messages reach a running session. It stays off until you enable it in Hermes: `xenonet doctor` says whether it is installed, enabled and working.
- **Restarts and crashes.** State files are written whole and flushed, so two writers or a crash can't leave a half file. A host key left half-written is replaced. An install lock left empty by a crash no longer blocks updates after 30 seconds. The console reads its state again when the service comes back.
- **Lower memory.** Indexing a large transcript takes about 154 MB instead of 358 MB, and starting with a day of busy transcripts takes about 182 MB instead of 511 MB.
- **Clearer first run.** When XenoNet isn't running, commands say to run `xenonet service start`. `xenonet update --check` and `xenonet service status` answer in words. Usage mistakes in `live`, `decide` and `refusals` exit with 2, like every other command, and `--help` lists every subcommand.
- **Provider checks.** The daily check now follows Grok Build's real release files, reads Grok's and Hermes's data formats from their source, and reads Hermes's database version, so a change in any of them is caught the day it ships.

## Updating

1. Update Desktop. On Windows, open **Updates** and choose **Restart and update**. On a Mac, replace XenoNet in Applications with the copy from the new disk image, and open it.
2. Update the Tools, then the Service: in **Updates**, or with `xenonet update tools` and then `xenonet update service`.
3. To follow Hermes live, run `xenonet connect hermes`, then enable the plugin in Hermes as the command says.

`SHA256SUMS.txt` lists checksums for the downloads.
