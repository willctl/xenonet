# XenoNet 0.5.2

In a network, the console now looks the same from every machine: each session is labelled with its machine, and the load panel shows the whole network. A Service update no longer cuts the gateway off from the other machines, and a machine whose gateway stops answering now says so. Grok Build sessions show their whole replies, thoughts, tokens and cost. Desktop and Tools are 0.5.2, the Service is 0.5.3 and the Mac tray is 0.4.1.

## Network mode

- Every session, alert, Needs-you row and inspector names its machine, this one's too, with a "here" mark ("studio · here").
- The load panel becomes **Machines**, and its rings show the network's totals:
  - **CPU** across every thread;
  - **RAM** summed;
  - **GPU** as the mean of all GPUs, naming the busiest.

  Stacked bars show each machine's share, with a row per machine under them. An offline machine is dimmed and left out of the sums.
- Click the panel's title or a machine's row to open the **Machines** view: the network's figures, a card per machine with its hardware, live load and sessions, filters by machine, platform and GPU, and a table to compare them.
- Each machine's load reaches the consoles of window hosts while they're open, every few seconds. Turn it off for a machine with **Share load with the network** in its Network panel, or `xenonet net set --no-share-load`. A console on a machine that isn't a window host shows the others from what their sessions report, without their load.

## The gateway stays reachable

- The Service now runs from `components/service/active`, a folder that stays put across updates. A firewall that allowed the gateway once keeps allowing it.
- The doctor's new check, **Other machines can reach this gateway**, warns when the Mac's firewall blocks the gateway, and gives the exact steps to allow it.
- If a machine's link to the gateway stops getting answers, the link goes offline within about a minute and says why ("the gateway didn't answer in 35 s"), then reconnects. Before, it could keep saying it was linked while hearing nothing.

## Grok Build

- A reply streamed in many chunks is one whole message in live, transcripts, search and stats. Its thoughts are kept and shown as Claude Code's thinking is.
- Tokens and cost come from each session's `usage.json`, counted per turn. With a SuperGrok sign-in Grok often records no cost, so XenoNet shows the tokens and marks the cost unknown, not zero.
- A subagent's session links to its parent.
- Grok Build is in `xenonet spend`, the MCP servers' panel and cloud assistants' sources.

## Also

- A session's panel shows the permission mode its hooks report, such as plan or bypass, for Claude Code too.

## Updating

1. Update Desktop. On Windows, open **Updates** and choose **Restart and update**. On a Mac, replace XenoNet in Applications with the copy from the new disk image, and open it.
2. Update the Tools, then the Service: in **Updates**, or with `xenonet update tools` and then `xenonet update service`.
3. **On the network's gateway, if its firewall is on:** this update moves the Service to its fixed folder, so the firewall asks once more. On a Mac, choose **Allow**, or follow the doctor's steps. Later updates keep the same path.

Update every machine in a network: the Machines panel shows a machine's load once it's on 0.5.2.

`SHA256SUMS.txt` lists checksums for the downloads.
