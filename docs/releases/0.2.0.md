# XenoNet 0.2.0

XenoNet can now show every refusal it has saved, suggest which session should take a task, and start agents in sandboxes you review first. Service and Tools are both 0.2.0.

## Provider refusals

Choose **Review provider refusals** in the command palette to search the refusals XenoNet has saved. Filter by provider, outcome, model, category, saved context or date, and sort the results. Select a record to read its provider signal and session details. Its saved request loads only when you ask for it. Results come in pages, so records past the old limit of 500 are searchable too. Browsing leaves context recording as it was.

## Agent workflows

The command palette has four new entries for handing work to agents. Each one shows what it will send or run before it does, and none of them runs on its own. The [agent workflows guide](https://github.com/willctl/xenonet/blob/main/docs/guide/integrations.md) has the details.

- Route task asks JevRouter, through your OpenRouter decision key, whether Codex, Claude Code or a person should take a task. You see the exact request before it goes out. A suggestion never starts an agent, and the saved record keeps a hash of the task instead of its text.
- Review decisions lists past suggestions and lets you record how each one turned out.
- Launch sandbox starts Pi, Codex or Claude Code in an OpenShell sandbox you have installed. You check the command, the policy file and any project upload first. Sandboxes keep running after XenoNet closes, and XenoNet deletes one only after you review the deletion and confirm it. On Windows, OpenShell runs in WSL.
- Review Pi runs reads model, token, cost and tool counts from Pi's session files once you turn it on, and imports pi-harness JSON exports. It leaves out prompts and tool content.

Sending a task, launching a sandbox and deleting one happen only in XenoNet's own window. The console driver and console MCP can browse these records but can't act on them.

## Fewer false stall warnings

Searches, paging and polling no longer show "may be stuck" just because the same tool runs several times. A retry warning now needs the same call to fail again and again. A failure warning needs at least five failures in a row over a minute. Waiting for your answer or approval doesn't count as stalled.

## Gateway tokens

A session can now ask for an actor's gateway token, with the `ask_gateway_token` tool in Claude Code or Codex, or with `xenonet gateway token <slug>` in a terminal. The ask makes no token. It leaves a card in XenoNet's window saying whose app it's for and who asked, and XenoNet makes the token only when you choose **Allow** there. The session never sees the token, and the actor's old token keeps working until you allow. In the connect steps the token stays masked until you choose **Show**, and **Copy token** copies it without showing it.

## Other changes

- A message for a session now waits for its main thread. Before, a subagent working in that session could take the message and mark it read, so the session never saw it.
- Token use always shows an OpenRouter row, with a way to set the key when none is stored or the provider rejects it.
- On Windows, startup no longer fails when checking the account takes longer than 10 seconds. XenoNet now waits up to a minute.

## Downloads

- On Windows, [XenoNet Setup](https://github.com/willctl/xenonet/releases/download/v0.2.0/XenoNet-Setup-0.2.0.exe) installs Desktop, Service and Tools.
- On an Apple silicon Mac, download [XenoNet for Apple silicon](https://github.com/willctl/xenonet/releases/download/v0.2.0/XenoNet-0.2.0-arm64.dmg). On an Intel Mac, download [XenoNet for Intel](https://github.com/willctl/xenonet/releases/download/v0.2.0/XenoNet-0.2.0-x64.dmg).
- The Desktop-only downloads and the Service and Tools archives are for XenoNet's updater and for [installs without Desktop](https://github.com/willctl/xenonet/blob/main/docs/guide/components.md).

## Updating

On Windows, open **Updates** and choose **Restart and update** for Desktop. Then install the Service and Tools updates there, or run `xenonet update all`.

On a Mac, replace XenoNet in Applications with the copy from the new disk image, and run `xenonet update all`. Your settings stay in place.

Without Desktop, `xenonet update all` is the whole update. The service update waits while XenoNet's terminals run, so close them first.

`SHA256SUMS.txt` lists checksums for the downloads.
